# Runbook: Refresh `/codegraph` After Code Changes

**When to use**: any non-trivial code change (added/renamed routers, new components, refactored modules, etc.) — the bundled AST graph at `web/public/codegraph/` falls out of date.

**Pre-conditions**:
- `graphify` CLI installed locally (`pip install graphifyy`, see `https://pypi.org/project/graphifyy/`).
- AWS Bedrock access (EC2 IAM role suffices on this instance — Bedrock Sonnet 4.6 region default `ap-northeast-2`).
- `boto3` available in the active Python env.

---

## One-shot script

```bash
./scripts/refresh_codegraph.sh
```

That's it. Internally:

1. **graphify update . --force** — re-extracts AST nodes/edges from the current source tree. *Recap from ADR-0010*: no LLM at this step; pure AST.
2. **bundle copy** — `cp graphify-out/{graph.html, graph.json, manifest.json, GRAPH_REPORT.md} web/public/codegraph/`.
3. **`scripts/label_codegraph_communities.py`** — Bedrock Sonnet labels each community (~3 min for 159). Outputs `community_labels.json` + `community_meta.json` sidecars + writes `community_labels`/`community_meta` keys into `graph.json`.
4. **In-place patch graph.html** — replaces the 1,751 baked-in `"community_name": "Community NNN"` JSON literals with semantic labels, so hover tooltips inside the iframe show real Korean names.

Total runtime ≈ 3 min (Bedrock-bound).

---

## Manual step-by-step

If you prefer to run each phase individually for inspection:

```bash
# Phase 1: AST extraction (fast, no LLM)
graphify update . --force

# Phase 2: bundle into Next.js public/
cp graphify-out/graph.html graphify-out/graph.json \
   graphify-out/manifest.json graphify-out/GRAPH_REPORT.md \
   web/public/codegraph/

# Phase 3: Bedrock labelling (~3 min, all 159 communities)
python3 scripts/label_codegraph_communities.py

# OR: dry-run first to inspect representative nodes per community
python3 scripts/label_codegraph_communities.py --dry-run

# OR: cap the LLM calls to top-N largest communities (rest get auto-label)
python3 scripts/label_codegraph_communities.py --limit 30

# Phase 4: in-place patch graph.html node.community_name fields
python3 - <<'PY'
import json
labels = json.load(open('web/public/codegraph/community_labels.json'))
html = open('web/public/codegraph/graph.html').read()
import re
patched = 0
for cid, label in labels.items():
    label_esc = label.replace('"', '\\"')
    pattern_re = re.compile(r'("community":\s*' + cid + r',\s*"community_name":\s*)"[^"]*"')
    new_html, n = pattern_re.subn(r'\1"' + label_esc + r'"', html)
    if n: html = new_html; patched += n
print(f'Patched {patched} community_name occurrences')
open('web/public/codegraph/graph.html', 'w').write(html)
PY
```

## Verification

After refresh, check:

```bash
# Bundle counts
ls -la web/public/codegraph/
# Expect: graph.html, graph.json, manifest.json, GRAPH_REPORT.md,
#         community_labels.json, community_meta.json

# Community label coverage
jq 'keys | length' web/public/codegraph/community_labels.json
# Expect: equal to community count in graph.json (currently 159)

# Sample meta
jq '.["0"]' web/public/codegraph/community_meta.json
# Expect: { label, description, key_concepts[], top_files[], node_count }

# graph.html no longer contains "Community NNN" placeholder
grep -c '"community_name": "Community ' web/public/codegraph/graph.html
# Expect: 0 (all 1,751 occurrences patched to semantic labels)
```

## Troubleshooting

- **`graphify: command not found`** → `pip install graphifyy` (with double-y). The `graphify` CLI is bundled with the `graphifyy` package.
- **Bedrock `AccessDeniedException`** → IAM role lacks `bedrock:InvokeModel` on the model ARN. Add the policy or run from a host where the API is configured.
- **Bedrock returning malformed JSON** → Sonnet sometimes wraps response in ```json fences. The script's `_JSON_BLOCK` regex handles this; if it fails, check `--dry-run` output to see prompt structure and tune `_enrich_one()` if needed.
- **Stale labels after refresh** → Phase 4 (graph.html in-place patch) didn't run or graph.html was regenerated by graphify after the patch. Re-run the manual Phase 4 block.
- **graphify-out/ exists but should be committed?** → No. `graphify-out/` is `.gitignore`d; only the bundled snapshot at `web/public/codegraph/` is version-controlled.
