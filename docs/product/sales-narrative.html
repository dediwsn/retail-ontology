상품은 PIM에, 성분은 규제 스프레드시트에, 회원 RFM은 CRM에, 재고는 WMS에. MD가 궁금해하는 것은 대부분 이 네 곳을 동시에 건너가는 질문이고, 그래서 2주짜리 분석 요청이 됩니다. Ontology Retail은 이 사일로를 하나의 지식그래프로 접고, 그 위에 13개의 의사결정 화면을 올립니다.

Ontology Retail folds those silos into one knowledge graph and puts thirteen decision surfaces on top of it.

데이터 웨어하우스에서는 다중 CTE 지옥입니다. 그래프에서는 Cypher 한 문장입니다. 그리고 답과 함께 그 답을 만든 경로가 같이 나옵니다.

02

하나의 온톨로지, 다섯 개의 레이어

One ontology, five layers

레이어는 순서대로 쌓였고, 각 레이어는 아래 레이어를 재사용합니다. 물류가 만든 Region 노드를 멤버십이 그대로 쓰기 때문에, “가장 이탈 위험이 높은 시도”와 “가장 배송이 취약한 시도”가 같은 지도 위에서 비교됩니다.

The layers stack, and each reuses the one below. Membership reuses the very Region nodes logistics created — so “our highest-churn province” and “our worst-served province” are comparable on the same map, by construction.

03

13개 화면. 각각이 하나의 실제 의사결정.

Thirteen surfaces. Each one a real decision.

시나리오는 기능 목록이 아니라 누가 무엇을 결정하는가로 정리되어 있습니다. 상단의 페르소나를 바꾸면, 페르소나에 따라 답이 달라지는 9개 화면 (A·D·E·G·I·J·K·L·M)이 한 번에 다시 잘립니다. 나머지 4개(B 대화·C 인사이트·F 대체재·H 물류)는 현재 페르소나 파라미터를 받지 않습니다 — B는 대신 대화 메모리로 맥락을 이어갑니다.

These are organised by who decides what, not by feature. One persona switch at the top re-slices the nine scenarios whose answer depends on it (A·D·E·G·I·J·K·L·M). The other four — B chat, C insights, F substitute, H logistics — take no persona parameter today; B carries context through conversational memory instead.

04

차별점

The differentiator

내부 데이터만 보는 VIP 점수는, 못 보는 것이 있습니다.

A VIP score built on internal data has a blind spot.

내부 거래는 우리가 판 것만 알려줍니다. 그 회원이 같은 카테고리에서 밖에서 얼마를 쓰는지는 모릅니다. 그래서 “LTV 상위 = VIP”라는 정의는 이미 우리 것인 지갑에 예산을 씁니다.

Internal transactions only tell you what we sold — never what that member spends in the same category elsewhere. So “top LTV = VIP” spends the budget on the wallet we already own.

Scenario M은 외부 소비 패널을 OVERLAPS_WITH 브리지로 내부 카테고리에 붙여 회원 × 카테고리 단위의 지갑 점유율을 만듭니다.

Scenario M bridges an external consumption panel onto internal categories through OVERLAPS_WITH, producing wallet share per member per category.

05

왜 믿을 수 있는가

Why it holds up

LLM 데모의 문제는 대부분 “그럴듯한 답”입니다. 이 플랫폼은 그럴듯함 대신 근거를 냅니다.

Most LLM demos fail on plausibility — an answer that sounds right. This one produces evidence instead.

결정론Deterministic

안전성 판정은 모델 판단이 아닙니다

Safety is traversal, not judgement

회피 성분 판정은 그래프 순회입니다. 같은 입력이면 같은 결과가 나옵니다. 규제 대응에서 이건 타협 불가 조건입니다.

Avoid-list checks are graph traversal, so the same input always yields the same verdict — non-negotiable for regulatory work.

재현성Reproducible

데모가 흔들리지 않습니다

The demo never drifts

모든 합성 ID와 확률은 SHA-1 시드 PRNG, 모든 날짜는 고정 기준일 기반. 미팅 직전에 재적재해도 리허설과 동일합니다.

Every identifier and probability comes from a SHA-1-seeded PRNG against a fixed anchor date. A reload before the meeting matches the rehearsal exactly.

운영 부담이 AWS에 남습니다

The operating burden stays with AWS

상시 GPU 없음, 프로비저닝된 모델 처리량 없음, 관리형 검색·그래프. 7일 비용 뷰와 이상 탐지 알림이 기본 포함입니다.

No always-on GPU, no provisioned model throughput, serverless search and managed graph — with a 7-day cost view and anomaly alerting built in.

그리고 회의적인 기술 구매자를 위한 한 가지 더 — /codegraph는 이 플랫폼을 자기 자신에게 겨눈 화면입니다. 소스 151개 파일에서 뽑아낸 1,751 노드 · 2,217 엣지 · 159 커뮤니티를 같은 방식으로 탐색합니다. 그래프 추출에는 LLM이 쓰이지 않았고, LLM은 커뮤니티 이름을 붙이는 데만 쓰였습니다. 이 접근이 리테일에서만 되는 게 아니라는 증거입니다.

And for the sceptical technical buyer: /codegraph points the platform at itself — 1,751 nodes, 2,217 edges and 159 communities extracted from 151 source files, explored the same way. No LLM was used to build the graph; the model only labelled the communities. It is the proof that the approach isn't retail-specific.

  • ALB 인그레스를 CloudFront 프리픽스 리스트로 제한 — 인터넷에서 오리진 직접 접근 불가
  • ALB ingress restricted to the CloudFront prefix list — direct internet-to-origin is impossible
  • API의 완전한 RS256 검증 — JWKS 서명 · 발급자 · 만료 · audience (1시간 TTL 캐시)
  • Complete RS256 verification at the API — JWKS signature, issuer, expiry and audience (1-hour TTL cache)
  • Cypher 전 구간 파라미터 바인딩 — 사용자 입력이 질의 코드가 되지 않음
  • Every Cypher parameter bound, never interpolated — user text never becomes query code
  • Bedrock Guardrails 입·출력 적용 + 개입 로그 열람
  • Bedrock Guardrails on input and output, with a browsable intervention log
  • Neptune · OpenSearch · Aurora 전부 프라이빗 서브넷
  • Neptune, OpenSearch and Aurora all in private subnets
  • CI 4개 잡 · ADR 13건 · 런북 5건 · 이중 언어 문서
  • Four CI jobs · 13 ADRs · 5 runbooks · bilingual documentation

30분 시연 진행안

The thirty-minute demo

시작할 때 페르소나를 캠퍼로 고정하고 끝까지 바꾸지 마십시오. 13개 화면이 같은 사람의 이야기로 이어질 때 설득력이 생깁니다.

Set the persona to 캠퍼 (camper) at the start and never change it. The pitch works because all thirteen screens stay one person's story.

0–4A · 검색A · Search 한국어로 자연스럽게 묻고, 결과 옆 서브그래프를 가리키며 왜 이게 나왔는지가 같이 나옵니다. 페르소나를 바꿔 결과가 다시 잘리는 것을 보여주십시오. Ask in plain Korean, then point at the subgraph: the answer arrives with its reason attached. Switch persona to show the results re-slice.
4–8E · 안전성E · Safety 임산부 프로파일로 전환. 위반 성분 이름을 짚으며 이건 모델 판단이 아니라 그래프 순회입니다. Switch to the pregnancy profile, name the violating ingredient: this is traversal, not a model judgement.
8–13C · MD 인사이트C · MD Insights 요약이 토큰 단위로 흐르는 동안 기다렸다가 차트가 뜨면 집계가 먼저 돌고 모델은 그 숫자를 설명만 합니다 — 숫자를 지어내지 않습니다. Let the summary stream, then when the chart lands: the aggregation ran first — the model narrates those numbers, it doesn't invent them.
13–17L · 커버리지L · Coverage 반경 슬라이더를 움직이며 단일 KPI를 보여줍니다. 이 숫자 하나가 증설 사업성 문서의 첫 줄입니다. Move the radius slider against the single KPI: this number is line one of the expansion business case.
17–24M · VIP 빌더M · VIP Builder 여기가 클라이맥스입니다. 점유율 0%인 캠핑 장비를 짚고 내부 데이터만 보면 이 회원은 평범한 실버입니다. 5개 탭을 차례로 넘깁니다. The climax. Point at the 0%-share camping-gear row: on internal data alone, this member looks like an ordinary Silver. Then walk the five tabs.
24–28B · 에이전트B · Agent 도구 호출 패널이 흐르는 것을 보여주며 추측이 아니라 도구를 호출해서 답합니다. Show the tool-call panel streaming: it calls tools to answer — it doesn't guess.
28–30운영 · 온톨로지Ops · Ontology 평가 점수판, 가드레일 로그, 표준 커버리지를 빠르게 스크롤합니다. 기술 구매자를 위한 마무리입니다. Scroll quickly through the evaluation scoreboard, guardrail log and standards coverage — the close for the technical buyer.

시간이 더 있으면 I · J · K(이탈 · 획득 · 승급)를 CRM 담당자에게, H를 SCM 담당자에게 추가로 붙이십시오. 사이드바 로고는 클릭 한 번으로 바뀝니다 — 미팅 전에 고객 로고로 맞춰두십시오.

With more time, add I · J · K for the CRM lead and H for the supply-chain lead. And the sidebar logo swaps with one click — set it to the customer's brand before you walk in.
